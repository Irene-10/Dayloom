# 日常工作台

把任务、习惯和知识卡片放在同一个清爽的工作台。默认提供六个项目领域：工作事业、长期学习、运动健康、兴趣爱好、日常生活、副业探索；四项打卡：早睡、运动、阅读、学习。项目和打卡可在设置中改名、换色、新增或删除。删除打卡会保留历史记录，月份表同时显示心情与打卡情况。所有人的初始内容都是空白的。

## 本地运行

需要 Node.js 24 或更新版本。不需要安装 npm 依赖。

```bash
node server.js
```

打开 `http://127.0.0.1:8787`。浏览器内的数据会自动保存在本机；在「设置」可以导出、导入完整 JSON 备份。直接双击 `index.html` 也能使用离线功能，但无法登录同步服务。

## 电脑与手机同步

完整部署、迁移与验证步骤见 [docs/sync-deployment.md](docs/sync-deployment.md)。

本项目包含一个同源 Node 服务和 SQLite 数据库。服务会为每个账号分开保存数据，密码用 scrypt 加盐散列，登录使用 HttpOnly Cookie。登录后，本地修改会上传；另一台设备用同一网址登录同一账号即可取得数据。若两台设备同时修改而版本冲突，系统会暂停同步并要求明确选择保留哪份，避免静默覆盖。请在冲突处理前先导出 JSON 备份。

本地服务默认只监听 `127.0.0.1`。若要手机访问，需把服务部署在手机和电脑都能访问的地址。生产环境必须使用 HTTPS、持久化磁盘、常规数据库备份，并设置 `PUBLIC_ORIGIN` 为站点的完整 HTTPS 来源。可以通过环境变量设置 `HOST`、`PORT`、`WORKTABLE_DATA_DIR`。若临时在可信局域网测试，可把 `HOST` 设为 `0.0.0.0`，但不要把明文 HTTP 服务直接暴露到公网。

SQLite 数据库默认写入操作系统用户数据目录（Windows 为 `%LOCALAPPDATA%/EverydayWorktable`），**不在代码仓库里**。仓库还忽略任何 `*.sqlite`、`.env` 和 `private-data/`。不要把运行时数据库、账号信息或个人备份提交到 GitHub。GitHub 用来托管源码；GitHub Pages 只能运行静态前端，不能承载这个同步服务或数据库。

## 手机安装

网页支持窄屏布局。通过 HTTPS 打开后，可使用浏览器的「添加到主屏幕」安装为 PWA。离线时数据留在设备本机，恢复联网后会尝试同步。此版本还不是 iOS / Android 原生安装包。

## 数据说明

- 本地：任务、设置等存在浏览器 localStorage；知识卡片存在 IndexedDB。
- 云端：登录后，完整数据按账号存在 SQLite。
- 导入仅接受本产品的 JSON 备份，不会自动读取个人版工作台的数据。
- 云端状态是完整快照；多人实时协作不是此版本的目标。

运行 `node --test tests/sync.test.js` 可执行后端账号隔离与版本冲突测试。公开部署前仍应进行独立安全审查、HTTPS 与备份恢复演练。
