# Windows 使用指南

Dayloom 是在电脑上运行、通过浏览器使用的个人管理工具。当前为桌面测试版，没有安装包；首次安装 Node.js 后，以后双击启动文件即可运行。

## 第一次启动

1. 从项目 GitHub 页选择绿色的 **Code → Download ZIP**。如果拿到的是发布压缩包，直接使用该压缩包。
2. 右键压缩包，选择“全部提取”。把解压后的文件夹保存在方便找到的位置，例如 `D:\Apps\Dayloom`。不要在压缩包内部直接运行。
3. 从 [Node.js 官网](https://nodejs.org/) 安装 **24 或更高版本**，安装时使用默认选项。Dayloom 使用 Node 自带的 SQLite，不需要额外安装数据库或运行 `npm install`。
4. 打开解压后的文件夹，找到 `server.js` 和 `Start-Dayloom.cmd`，双击 **Start-Dayloom.cmd**。
5. 启动窗口显示 `Dayloom: http://127.0.0.1:8787`、`本机模式 · 无需登录` 和数据文件路径后，用 Chrome 或 Edge 打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)。
6. 在“设置”中修改称呼，添加一条任务或笔记。等左下角显示“已保存到电脑数据库”，保存才算完成。

`127.0.0.1` 指当前这台电脑。别人下载并启动自己的 Dayloom 后，也打开同一个地址，但看到的是他们自己的内容。默认不需要购买服务器、注册账号或连接互联网。

## 每次怎么打开和关闭

- 下次继续使用：双击同一个 `Start-Dayloom.cmd`，再打开浏览器书签。
- 使用时保留启动窗口，可以最小化。只打开浏览器不能启动数据库服务。
- 关闭前等“已保存到电脑数据库”，关闭页面，再在启动窗口按 `Ctrl+C`。如果询问是否终止批处理，输入 `Y`。
- 关闭或重启电脑不会删除已写入数据库的内容；重新启动后继续使用。
- 尚未保存时关闭页面，浏览器通常会提醒。不要把浏览器缓存中的“待保存”当成已经写进数据库。

## 不使用双击启动文件的方式

在包含 `server.js` 的文件夹里点击资源管理器地址栏，输入 `powershell` 并回车。然后分别执行：

```powershell
node --version
node server.js
```

第一行应输出 `v24.x.x` 或更高；第二行启动服务。后续使用步骤相同。

## 数据在哪里

全新安装默认使用 `%LOCALAPPDATA%\Dayloom\worktable.sqlite`。按 `Win+R`，输入 `%LOCALAPPDATA%\Dayloom` 就能找到目录；“设置 → 电脑存储”显示准确路径。

如果旧版 `%LOCALAPPDATA%\EverydayWorktable\worktable.sqlite` 已存在，程序会继续使用旧目录，防止更新后误以为原数据丢失。它仍然是 Dayloom 的数据。旧版账号内容保持独立，参见下文迁移说明。

本机模式的一份数据库由这个 Windows 用户运行的服务管理。同一地址下的不同浏览器可以读到它。没有浏览器账号隔离：能使用这个 Windows 账户的人也可能访问数据。不建议在共用 Windows 账户中存放私密内容。

浏览器保留一份缓存。只有数据库保存成功的内容，才可以在清理浏览器网站数据后重新读取。若服务中断，左下角会提示暂存在浏览器；重启服务并等待重试，或者在设置里点击“重新连接本机服务”。不要在补存前清缓存。

## 旧版和离线体验的数据怎么搬过来

直接双击 `index.html` 是浏览器体验模式，没有 SQLite 保存。更换浏览器、清除网站数据或使用无痕窗口可能使这份数据不可用。

从 HTML 体验版迁移：先在原页面“设置 → 导出 JSON”，再启动本机版，打开 `http://127.0.0.1:8787`，选择“设置 → 导入 JSON”。导入会替换当前工作空间，先备份目标空间的已有内容。

从旧版账号模式迁移：先在旧版登录并导出 JSON，再进入新版本机模式导入。也可在 PowerShell 设置 `$env:DAYLOOM_MODE='accounts'` 后运行 `node server.js` 访问原账号；双击启动文件始终使用本机模式。

如果浏览器和数据库已经分别有内容，Dayloom 会让你选择保留哪份。先导出当前浏览器备份；需要比较时，可读取数据库并再导出一份。两份内容不会自动合并。

## 备份与升级

最方便的备份是“设置 → 导出 JSON”，把文件保存在自己选定的位置。它包含任务、知识卡片、习惯、心情和设置；备份文件没有加密，请妥善保管。

升级前导出 JSON，停止启动窗口，再解压新版本的代码，使用相同 Windows 用户启动。数据库放在代码目录外，替换代码不会主动删除数据库。切换数据目录前先备份。

如果要备份整个数据库，请先关闭服务再复制整个数据目录，包括可能存在的 `-wal` 和 `-shm` 文件；服务运行期间不要只复制主 `.sqlite` 文件。需要在线备份的部署者参见[同步部署指南](sync-deployment.md)。

## 可选 AI 阅读

不配置 API 也可以使用“今日重读”。如需跨卡片“知识碰撞”，在 **设置 → AI 阅读** 填写兼容 `/chat/completions` 的 API 地址、模型名称和 API Key，然后测试连接。通常填写服务商提供的 `/v1` 地址即可；本地 Ollama 可以使用它的 OpenAI 兼容地址，并可能不需要 Key。

每次生成前都会显示将发送的卡片，只有点击“确认并生成”才会调用接口。API Key 留在本机数据库，不进入 JSON 备份；详细边界见[数据与隐私说明](privacy.md)。

## 常见问题

**启动窗口说找不到 Node.js。** 安装 Node.js 24+ 后关闭旧终端，重新双击启动文件；用 `node --version` 检查。

**打开地址后显示无法连接。** 确认启动窗口仍在运行，而且打开的端口与窗口显示一致。直接双击 HTML 不会启动服务。

**端口被占用。** 先确认是否已经开着一个 Dayloom。若是其他程序占用了端口，可在 PowerShell 执行 `$env:PORT='8788'`，再执行 `node server.js`，访问 `http://127.0.0.1:8788`。不要停止不认识的进程；同一数据库尽量只运行一个服务。

**换浏览器后没有看到刚才的数据。** 检查是否使用相同的本机服务地址、Windows 用户和数据目录，以及之前是否显示保存成功。HTML 体验版和本机版是独立空间。

**出现版本冲突。** 两个页面可能修改了同一份内容。先导出备份，再选择读取数据库或保留当前浏览器内容；选择会替换其中一个版本。

**数据太大无法保存。** 当前数据库接口接收的完整快照有约 10 MB 上限。出现提示时先导出 JSON，整理内容后重试；不要清缓存或关闭尚未备份的页面。
